# Правила работы над проектом

## Общие принципы
- Пиши **только по-русски**; если данных недостаточно — остановись и задай вопросы вместо догадок.
- Не соглашайся автоматически: проверяй мои утверждения, указывай риски/альтернативы, задавай наводящие вопросы.
- По умолчанию выбирай безопасные решения и следуй best practices безопасности.

## Режимы работы и границы
- Делай ровно то, что я попросил: никаких лишних действий, кода, рефакторинга и «улучшений» без запроса.
- Всегда начинай с чтения памяти проекта — `~/.claude/projects/-Users-fvasilyev-Desktop-Staff-Portfolio/memory/` (индекс `MEMORY.md`) — и учитывай её как источник контекста.
- Сначала диагностика, затем изменения: не правь код, пока я явно не разрешу.

## Процесс диагностики (обязателен)
- Сначала найди проблему в коде/конфиге/логах; до этого не предлагай правки.
- Уточни задачу и сформулируй план короткими шагами.
- Проверь гипотезу 3 раза и укажи уверенность в процентах.

## Формат ответа на баг/задачу
Всегда используй шаблон:
- ПРОБЛЕМА: …
- ГДЕ ИМЕННО: …
- КАК БУДЕМ РЕШАТЬ (план): …
- ЧТО ИЗМЕНИТСЯ ПОСЛЕ: …
- КАК ПРОТЕСТИРОВАТЬ ПОСЛЕ РЕШЕНИЯ: (конкретные действия в боте) …
- УВЕРЕННОСТЬ: X%
- ВОПРОС: Могу ли я начать исправление?

## Изменения, тесты, отчёт, память
- Цикл работы: предложи тесты/проверки → (после разрешения) внеси минимальные изменения → убедись, что проверки проходят.
- Изменения делай минимальными; не дублируй общий код (если нужно — выноси в модуль, но только по необходимости).
- После каждого изменения: краткий отчёт (что/почему/какие файлы) и обновление памяти (только релевантные файлы).

# Цветовые переменные проекта

**Единственный источник правды** — блок `:root` в [app/globals.css](app/globals.css). Тема только светлая (`color-scheme: light`, `--background` светлый). Никаких hex/rgb-значений в компонентах — только переменные ниже.

## Базовые токены (`:root`)

| Переменная      | Значение             | Назначение                                   |
| --------------- | -------------------- | -------------------------------------------- |
| `--background`  | `rgb(242, 242, 242)` | Фон страницы                                 |
| `--border`      | `rgb(214, 214, 218)` | Тонкие линии, разделители (hairlines)        |
| `--card`        | `rgb(255, 255, 255)` | Поверхности / карточки                       |
| `--body`        | `rgb(48, 48, 52)`    | Текст body — абзацы                           |
| `--muted`       | `rgb(110, 110, 115)` | Вторичный / приглушённый текст               |
| `--foreground`  | `rgb(20, 20, 22)`    | Сильный текст — заголовки, акценты            |

## Tailwind-алиасы (`@theme inline`)

Эти алиасы ссылаются на базовые токены и включают утилитарные классы Tailwind:

| Алиас (переменная)      | Ссылается на   | Классы Tailwind                              |
| ----------------------- | -------------- | -------------------------------------------- |
| `--color-background`    | `--background` | `bg-background`                              |
| `--color-foreground`    | `--foreground` | `text-foreground`, `bg-foreground`           |
| `--color-body`          | `--body`       | `text-body`                                  |
| `--color-muted`         | `--muted`      | `text-muted`                                 |
| `--color-card`          | `--card`       | `bg-card`                                    |
| `--color-border-subtle` | `--border`     | `border-border-subtle`                       |

## Кривые анимации (не цвета, но тоже общие токены)

| Переменная            | Значение                            | Назначение                     |
| --------------------- | ----------------------------------- | ------------------------------ |
| `--ease-out-strong`   | `cubic-bezier(0.23, 1, 0.32, 1)`    | Появления, reveal, preloader   |
| `--ease-in-out-strong`| `cubic-bezier(0.77, 0, 0.175, 1)`   | Симметричные переходы          |

## Правила использования цвета
- Используй **только** переменные/классы выше — не хардкодь `#fff`, `rgb(...)`, именованные цвета.
- В CSS обращайся через `var(--foreground)` и т. п.; в JSX предпочитай утилитарные классы Tailwind (`text-muted`, `bg-card`, …).
- Новый цвет добавляй сначала как токен в `:root`, затем алиас в `@theme inline` — и только потом используй. Одно место правды.
- Иерархия текста: `--foreground` (заголовки/акценты) → `--body` (абзацы) → `--muted` (вторичное).
- Тема только светлая — не добавляй тёмную без отдельного запроса.

# Скиллы (`~/Desktop/skills-main/skills`)

Набор скиллов по анимации и дизайну. Часть вызывается автоматически по контексту, часть — **только по явному запросу** (`disable-model-invocation: true`).

## Автоматически по контексту (можно вызывать, когда задача подходит)

| Скилл                          | Когда использовать                                                                                     |
| ------------------------------ | ----------------------------------------------------------------------------------------------------- |
| `animation-vocabulary`         | Нужно назвать эффект: «как называется, когда…». Только даёт термин, не проектирует и не реализует.     |
| `apple-design`                 | Жестовый UI, spring-анимации, drag/swipe/sheet, прозрачные материалы, типографика, reduced-motion.    |
| `emil-design-eng`              | Полировка UI, дизайн компонентов, решения по анимации и «невидимые» детали качества.                   |
| `find-animation-opportunities` | «Что здесь можно оживить?» — ищет места без анимации, где она уместна. Read-only, только предлагает.   |
| `improve-animations`           | «Улучши/проаудируй анимации» — аудит всей моушен-базы + план правок. Read-only, не применяет правки.   |

## Только по явному запросу (`/имя-скилла`)

| Скилл              | Когда использовать                                                                                  |
| ------------------ | -------------------------------------------------------------------------------------------------- |
| `review-animations`| Ревью анимаций по высокой планке (философия Emil Kowalski). По умолчанию флагует, одобрение нужно заслужить. |
| `pick-ui-library`  | Подобрать библиотеку под фронтенд-задачу (числа, OTP, графики, command menu, DnD, тосты и т. д.).   |
| `prototype`        | Собрать несколько разных вариантов UI-куска за визуальным пикером, чтобы вживую выбрать лучший.     |

## Правила использования скиллов
- Реализацию анимаций делай в терминах токенов проекта: используй `--ease-out-strong` / `--ease-in-out-strong`, анимируй только `opacity` и `transform`, всегда добавляй ветку `@media (prefers-reduced-motion: reduce)` — как уже сделано в [app/globals.css](app/globals.css).
- Для правок конкретного диффа — `review-animations`; для поиска новых мест — `find-animation-opportunities`; для аудита всей базы и плана — `improve-animations`.
- Скиллы с пометкой «по явному запросу» сам не запускаю — жду команду `/имя-скилла`.
